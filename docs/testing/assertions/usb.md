# Assertions: USB host controller (xHCI) and HID boot keyboard rules

Source: NOLX M9 -- `ROADMAP.md` (Devices and drivers, Input: USB xHCI to HID) and `crates/nolx-usb-core`.
The rules cover the xHCI capability and operational register offsets, the port status bits and their
write-one-to-clear behaviour, the transfer request block layouts the controller reads and writes, and
the HID boot protocol keyboard report, turned into the same key events the PS/2 decoder produces. The
kernel now moves bounded direct-root boot-HID rings using MSI/MSI-X-scheduled idle service when
available, with explicit polling fallbacks. This is not a general USB stack.

The xHCI register offsets and bit positions (CAPLENGTH, HCSPARAMS1, DBOFF, USBCMD, USBSTS, PORTSC and
its change bits, port register sets at 0x400 with 0x10 stride), the TRB type numbers and cycle, toggle,
and interrupt-on-completion bits, the event completion code and slot and port fields, and the HID boot
keyboard report layout and modifier bits are from the xHCI and USB HID specifications as recalled, not
yet checked against the documents. Verify them before the rows are promoted.

Rows are pipe-delimited: `ID | specification reference | status | test`.

## USB 2.0 hubs (M9)

A hub is not a HID device with an odd descriptor: its class sits at the *device* level, its ports
are read with class requests aimed at "other", and every device below it is addressed by a route
string in its slot context. The rows below cover the rules as bytes (`nolx-usb-core::hub`), then
the live behaviour behind QEMU's `usb-hub`.

USB-032 | NOLX M9 Hub class descriptor: a hub is recognised by `bDeviceClass` 9 rather than an interface class; the descriptor is at least seven bytes and at most eleven, its declared port count is 1..15, its removable bitmap is as long as the count requires, per-port/gang power switching, per-port over-current and the TT think time are decoded from `wHubCharacteristics`, and the power-on delay is the descriptor byte times two milliseconds; a missing bitmap, an impossible length, a zero port count and a wrong descriptor type are refused | tested-T1 | nolx-usb-core hub::tests::hub_descriptor_requires_its_bitmap, hub::tests::hub_characteristics_decode_into_the_three_answers_a_driver_asks_for, hub::tests::a_hub_is_recognized_by_its_device_class_not_its_interface
USB-033 | NOLX M9 Hub class requests: the hub descriptor is fetched as a class request to the device (`bmRequestType` 0xa0, type 0x29) because a standard-typed request for 0x29 stalls, while port status, clear-feature and set-feature target "other" (0xa3/0x23) with the port in `wIndex`; the status word uses bit 8 for power, bits 9/10 for low/high speed and reports full speed when neither is set, the change bits live in the second word (bit 0 connection, bit 4 reset), and the feature numbers name exactly the change bits being acknowledged | tested-T1 | nolx-usb-core hub::tests::the_hub_descriptor_is_read_with_a_class_request, hub::tests::port_status_bits_are_the_ones_the_specification_names, hub::tests::change_acknowledgements_name_exactly_the_bits_that_are_set
