# Assertions: M6 ELF image validation

Source: M6 ELF64 loader contract in `ROADMAP.md`. This slice validates a bounded fixed-address image plan; it does not yet map pages, apply relocations, start an interpreter, construct auxv, or enter ring 3.

ELF-001 | An x86-64 ELF64 executable yields only a bounded load plan whose file ranges, user virtual ranges, alignment, non-overlapping PT_LOAD segments, executable entry point, PT_INTERP path, PT_TLS template, and PT_GNU_STACK permission metadata have been validated | tested-T1 | `crates/nolx-exec-core/src/elf.rs` tests `plans_nonoverlapping_executable_and_data_segments`, `rejects_short_bad_magic_and_unsupported_images`, `rejects_program_header_table_outside_the_file`, `rejects_missing_or_unbounded_program_header_tables`, `rejects_more_load_segments_than_the_fixed_plan_holds`, `rejects_inconsistent_sizes_and_writable_executable_segments`, `rejects_out_of_user_range_overlapping_and_non_executable_entry`, `records_interpreter_tls_and_executable_stack_metadata`, `rejects_malformed_interpreter_path`, and `rejects_tls_not_backed_by_a_load_segment`; host tests passed in [workflow 38163939179](https://github.com/NeXuS4Dev/NOLX/actions/runs/38163939179).

ELF-002 | The second loader stage turns an accepted plan into page-fill operations (zero every touched page, then copy file bytes, so shared pages and bss tails come out byte-exact), an `ET_DYN` bias bounded to the user interval and sensitive to entropy, validated `R_X86_64_RELATIVE` relocations, and a SysV-shaped initial stack (argc/argv/envp/auxv/AT_RANDOM/AT_EXECFN, 16-byte-aligned `%rsp`) | tested-T1 | `crates/nolx-exec-core/src/image.rs` tests `page_fills_zero_every_touched_page_then_copy_file_bytes`, `page_fills_apply_the_bias_to_every_address`, `dyn_bias_is_entropy_sensitive_bounded_and_zero_for_exec`, `relative_relocations_are_collected_biased_and_bounded`, `unsupported_and_unmapped_relocations_are_refused`, `static_images_carry_no_relocations`, `stack_image_carries_argc_argv_envp_auxv_and_entropy`, `stack_image_rejects_bad_strings_and_oversized_requests`, and `empty_images_still_build_a_zero_argument_stack`.
ELF-003 | The embedded `hello` and `init` ring-3 programs are byte-deterministic static x86-64 ET_EXEC images that parse through the kernel's own load plan, place their entry bytes at their entry addresses when the page plan is applied, and carry exactly the lines the boot test waits for | tested-T1 | `crates/nolx-exec-core/src/image.rs` tests `the_embedded_programs_plan_like_the_kernel_will_load_them` and `the_embedded_programs_carry_the_lines_the_boot_test_waits_for`; generated by `tools/user-elf/gen.py`, checked by `make usercheck`.
